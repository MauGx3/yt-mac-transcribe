# yt-transcribe (`ytt`)

Turn a YouTube video into a text transcript on your Mac, in a few seconds.

Paste a link, and `ytt` saves the video's words as a text file, or as subtitles
(`.srt`, `.vtt`), a Markdown note, or JSON. It's built for Macs with Apple
silicon (M1 and later), and it all runs on your own computer.

**How it stays fast.** Most YouTube videos already have captions, either
written by the creator or generated by YouTube. `ytt` downloads those captions,
cleans them up and saves them. It doesn't download the video or the audio. Only
when a video has no usable captions does it transcribe the audio itself, with a
speech-to-text model that runs on your Mac. That part is optional and takes
longer.

There are two ways to use it:

| | Best for | What you need |
|---|---|---|
| **The Mac app** | Pasting a link and clicking a button. It also keeps a searchable library of your transcripts. | Xcode, to build the app once |
| **The `ytt` command** | Terminal users, scripts, batches and playlists | Python 3.8 or newer (macOS already has it) |

Both give the same transcripts. The app runs the `ytt` command for you.

## Before you start

You need:

1. **A Mac.** Apple silicon (M1 or later) is the target. The caption path also
   works on Intel Macs and on Linux, but transcribing audio on Intel will be slow.
   To check yours, open  menu → **About This Mac** and look at **Chip**.
2. **Homebrew**, the usual way to install command-line tools on a Mac. If
   `brew --version` in Terminal prints a version number, you have it. If not,
   follow the one-line install at [brew.sh](https://brew.sh).
3. **yt-dlp**, the tool that talks to YouTube. It's the only thing `ytt` really
   depends on:

   ```bash
   brew install yt-dlp
   ```

   YouTube changes often, and an old `yt-dlp` is the most common reason things
   stop working. Run `brew upgrade yt-dlp` every so often.

## Install the command-line tool

`ytt` isn't on Homebrew or PyPI yet, so you install it from a copy of this
repository. Pick one of the two options below.

**Option A: pipx (recommended).** This makes `ytt` available in every Terminal
window, with nothing to activate first.

```bash
brew install pipx
pipx ensurepath          # adds ~/.local/bin to your PATH; open a new Terminal window afterwards
git clone https://github.com/MauGx3/yt-transcribe.git
cd yt-transcribe
pipx install .
```

**Option B: a virtual environment.** Use this if you plan to change the code.
`ytt` only works in a Terminal window where you've run the `source` line.

```bash
git clone https://github.com/MauGx3/yt-transcribe.git
cd yt-transcribe
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

**Check that it worked:**

```bash
ytt --version
```

You should see something like `ytt 0.1.0`. If you see `command not found`, see
[Troubleshooting](docs/troubleshooting.md#ytt-command-not-found).

## Your first transcript

```bash
ytt https://youtu.be/aircAruvnKk
```

`ytt` prints its progress, then the path of the file it saved. Here that's a
`.txt` file named after the video's title, in the folder you ran the command
from. Open it with `open "<file name>.txt"`, or find it in Finder.

Put the link in quotes if it contains `&` (playlist links often do), so the
shell doesn't cut it short:

```bash
ytt "https://www.youtube.com/watch?v=aircAruvnKk&t=30s"
```

## Common tasks

| I want to… | Run this |
|---|---|
| Save to a specific folder | `ytt URL -o ~/Documents/transcripts` |
| Get subtitles for a video player | `ytt URL -f srt` |
| Get several formats at once | `ytt URL -f txt srt md` |
| Add `[mm:ss]` timestamps to the text | `ytt URL --timestamps` |
| Remove `[Music]`, `(applause)` and similar tags | `ytt URL --drop-sound-tags` |
| Get a transcript in another language | `ytt URL -l pt,en` (Portuguese first, then English) |
| See which caption languages a video has | `ytt URL --list-tracks` |
| Transcribe a whole playlist | `ytt "PLAYLIST_URL" --playlist -o playlist/` |
| Transcribe a list of videos | `ytt --batch urls.txt -o transcripts/` |
| Transcribe the audio myself, even if captions exist | `ytt URL --asr always` (see [the next section](#videos-without-captions-transcribing-on-your-mac)) |
| See what it's doing, step by step | `ytt URL -v --stats` |

**About batch files.** A batch file is a plain text file with one YouTube link
per line. Blank lines and lines that start with `#` are skipped. `ytt` waits one
second between videos so YouTube doesn't block you. Change that with
`--delay 3`.

**About languages.** `-l` takes a list in order of preference. `ytt` picks
creator-written captions in your first language if they exist, then YouTube's
automatic captions, and only then a machine translation. Each transcript records
which kind it used.

## Videos without captions: transcribing on your Mac

Some videos have no captions, or only captions too poor to use. You can set
`ytt` up to transcribe the audio on your Mac when that happens. This is
optional. Without it, `ytt` still works for every video that has captions.

By default (`--asr auto`), `ytt` uses captions when they're good and switches to
local transcription only when they're missing or fail a quality check (for
example, almost no words for a long video). `--asr never` turns local
transcription off, and `--asr always` uses it for every video.

You need `ffmpeg` (to convert the audio) and one speech-to-text engine. Pick
one:

| Engine | Good to know |
|---|---|
| **whisper.cpp** | Installs with Homebrew. You download a model file once. |
| **MLX Whisper** | Runs on the Apple silicon GPU and is often faster on M-series Macs. Downloads its model the first time you use it. |

If both are installed, `ytt` uses whisper.cpp. Choose one with
`--engine whisper-cpp` or `--engine mlx`.

### Option 1: whisper.cpp

```bash
brew install ffmpeg whisper-cpp
mkdir -p ~/.cache/whisper
curl -L -o ~/.cache/whisper/ggml-small.en.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.en.bin
```

The last command downloads the `small.en` model (about 500 MB). Homebrew's
`whisper-cpp` doesn't include a model download script, so this uses `curl`. If
you have the Hugging Face `hf` command, this does the same thing:

```bash
hf download ggerganov/whisper.cpp ggml-small.en.bin --local-dir ~/.cache/whisper
```

Then try it:

```bash
ytt https://youtu.be/aircAruvnKk --asr always
```

<details>
<summary>Where <code>ytt</code> looks for whisper.cpp model files</summary>

`ytt --model small.en` looks for `small.en` or `ggml-small.en.bin` in these
folders, in order:

1. `$YTT_MODEL_DIR`, if set
2. the current folder, then `./models`
3. `~/.cache/whisper`, then `~/.cache/whisper.cpp`
4. `/opt/homebrew/share/whisper-cpp` and its `models` subfolder
5. `/usr/local/share/whisper-cpp` and its `models` subfolder

You can also pass the full path to the file: `--model ~/models/ggml-small.en.bin`.
</details>

### Option 2: MLX Whisper (Apple silicon only)

```bash
brew install ffmpeg pipx
pipx ensurepath          # then open a new Terminal window
pipx install mlx-whisper
ytt https://youtu.be/aircAruvnKk --asr always --engine mlx
```

The first run downloads the model from Hugging Face, so it takes longer. To
download a model ahead of time, install the `hf` command
(`pipx install huggingface_hub`), then run:

```bash
ytt --engine mlx --download-model -m large-v3-turbo
```

`ytt --list-models` shows the models it knows and which ones are already
downloaded.

### Which model should I use?

Bigger models make fewer mistakes but run slower and take more disk space.
`small.en` is the default and a good place to start.

| Model | Size | Notes |
|---|---|---|
| `tiny.en` | ~75 MB | Fastest, roughest |
| `base.en` | ~150 MB | Fine for clear English speech |
| `small.en` | ~500 MB | **Default.** Best balance of speed and accuracy |
| `medium.en` | ~1.5 GB | Slow but strong |
| `large-v3` | ~3 GB | Best quality, and works for languages other than English |
| `large-v3-turbo` | | MLX only. Close to `large-v3` quality, much faster |

Models ending in `.en` only understand English. For other languages, use
`large-v3` (or `large-v3-turbo` with MLX). With `--engine mlx`, you can also
pass any Hugging Face repo id or a local model folder to `--model`.

## The Mac app

The app in [`macos/YTTranscribeApp`](macos/YTTranscribeApp/README.md) is a
window around the same tool:

- **Transcribe tab:** paste one video link, a playlist, or a list of links.
  Choose the output formats and click **Transcribe**.
- **Library tab:** every transcript you've made, searchable by title, link, or
  the words in the transcript.

Files go to `~/Documents/yt-transcribe` unless you change it in Settings.

**To get the app**, build it once with Xcode 15 or newer, on macOS 13 or newer:

1. Install Xcode from the App Store, and `yt-dlp` with `brew install yt-dlp`.
2. Open `macos/YTTranscribeApp/YTTranscribeApp.xcodeproj` in Xcode.
3. Choose the **YTTranscribeApp** scheme and **My Mac**, then press ⌘R.

The `ytt` tool is packed inside the app when it's built, so you don't need to
install it separately. The app also finds tools installed with Homebrew or pipx
(for example `mlx-whisper`), even when you open it from Finder.

The app isn't signed or notarized yet. If you copy a built app to another Mac
and macOS refuses to open it, go to **System Settings → Privacy & Security** and
click **Open Anyway**.

See the [app's README](macos/YTTranscribeApp/README.md) for settings and
troubleshooting.

## Cleaning up a transcript with a local AI model

Automatic captions often get names, homophones ("their" or "there") and
punctuation wrong. `ytt` can pass the finished transcript to a language model on
your Mac, which fixes the wording using the surrounding sentences. The timings
stay the same.

Your original file is never changed. The cleaned-up copy is saved next to it,
with `.rewritten` in the name: `My Video.txt` and `My Video.rewritten.txt`.

A ready-made runner for Apple silicon is included:

```bash
pipx install mlx-lm        # or: python3 -m pip install mlx-lm
ytt URL -f txt srt \
  --rewrite-command python3 tools/rewrite_with_local_model.py
```

Two things to know:

- `--rewrite-command` must come **last**. Everything after it is passed to the
  model runner, not to `ytt`.
- The first run downloads a model of a few gigabytes.

You can also connect any other local model, such as Ollama or llama.cpp. See
[Local context-aware rewriting](docs/local-rewriting.md) for how that works.

## Output formats and file names

| Format | Flag | What you get |
|---|---|---|
| Plain text | `-f txt` (default) | Readable paragraphs. Add `--timestamps` for `[mm:ss]` markers, or `--raw` for one line per caption. |
| SubRip subtitles | `-f srt` | For video players and editors. Overlapping captions are fixed. |
| WebVTT subtitles | `-f vtt` | For web video players. |
| Markdown | `-f md` | Title, channel and link at the top, then timestamped paragraphs. Good for notes apps. |
| JSON | `-f json` | Every segment with its start and end time, word timings when available, and where the text came from. For scripts and other programs. |

Files are named after the video's title, for example
`But what is a neural network.txt`. If you pass `-o` a folder (even one that
doesn't exist yet), files go in that folder. If you pass a file name ending in a
known extension, like `-o notes.md`, that exact file is written.

Every transcript records where its text came from: captions written by the
creator, YouTube's automatic captions, a YouTube machine translation, or local
transcription.

## All options

```text
ytt [URL ...] [options]

What to save
  -f, --format FMT ...     txt srt vtt json md            (default: txt)
  -o, --out PATH           output folder, or an exact file path
  -l, --langs LIST         language preference, e.g. pt,en (default: en)
      --timestamps         add [mm:ss] to txt/md output
      --raw                keep one line per caption cue
      --drop-sound-tags    remove [Music], (applause), and similar tags

Which videos
      --batch FILE         read URLs from a file (one per line, # for comments)
      --playlist           expand playlist URLs into their videos
      --list-tracks        list a video's caption tracks and exit

Local transcription
      --asr {never,auto,always}
                           auto: use captions, transcribe locally only when needed
  -m, --model NAME         model name, file path, or MLX repo id (default: small.en)
      --engine ENGINE      auto, whisper-cpp or mlx (default: auto)
      --download-model     download the MLX --model and exit
      --list-models        list models and whether they're downloaded, then exit

Being polite to YouTube
      --delay SECS         pause between videos (default: 1.0)
      --retries N          retry a failed video (default: 1)
      --cookies-from-browser BROWSER
                           use your browser's YouTube login (chrome, firefox, safari…)

Cache
      --no-cache           ignore the saved cache for this run
      --cache-ttl SECS     how long cached captions are kept (default: 604800, one week)
      --clear-cache        delete the cache and exit

Cleanup with a local model
      --rewrite-timeout SECS
                           how long the model may take (default: 300)
      --rewrite-command CMD ...
                           run a local model after transcription (must be last)

Other
  -q, --quiet / -v, --verbose / --stats / --version / -h, --help
```

**Exit codes**, for scripts: `0` when every video worked, `1` when none did, `2`
for a mistake in the command or a missing `yt-dlp`, and `3` when a batch or
playlist saved some transcripts but at least one video failed.

## Something went wrong?

The most common fixes:

- **Anything YouTube-related stopped working:** `brew upgrade yt-dlp`.
- **`ytt: command not found`:** open a new Terminal window after
  `pipx ensurepath`, or run `source .venv/bin/activate` again.
- **"no usable captions and the local ASR fallback is not installed":** the
  video has no captions `ytt` can use, and local transcription isn't set up. See
  [Videos without captions](#videos-without-captions-transcribing-on-your-mac).
- **"HTTP 429":** YouTube is limiting you. Wait a few minutes, use `--delay 5`,
  or add `--cookies-from-browser chrome`.
- **`CERTIFICATE_VERIFY_FAILED` in `ytt -v` output:** you're probably using
  Python from python.org, which needs one setup step. Run
  **Install Certificates.command** from `/Applications/Python 3.x/`.

[docs/troubleshooting.md](docs/troubleshooting.md) covers these and more, with
step-by-step fixes.

## How it works

```text
1. Ask yt-dlp for the video's details and the list of caption tracks (no download)
2. Pick the best track: creator captions → YouTube auto captions → machine translation
3. Download that track and clean it up:
     remove repeated lines, fix overlapping times, tidy whitespace
4. Check the quality. Missing or poor captions → transcribe the audio locally (optional)
5. Save the formats you asked for
```

Captions are cached in `~/.cache/yt-transcribe` for a week, and video details
for an hour, so running the same video again is quick and puts less load on
YouTube.

**How fast is it?** With captions, a transcript usually takes a few seconds, and
most of that is `yt-dlp` reading the video page. Local transcription takes
minutes rather than seconds. The time depends on the video's length, the model
and your Mac. To measure it on your machine, run `python3 tests/benchmark.py`.
It times the caption path for real. Its local transcription figures are
estimates.

## Privacy

- `ytt` connects to YouTube, through `yt-dlp`, to read video details and
  captions.
- Local transcription and local cleanup run entirely on your Mac. The only
  network use is downloading a model from Hugging Face the first time.
- Nothing is sent anywhere else. `ytt` has no accounts, analytics or telemetry.
- `--cookies-from-browser` lets `yt-dlp` read your browser's YouTube cookies on
  your Mac. They're used only to talk to YouTube.

## Known limits

- YouTube may block bursts of requests for a while. `--delay`, the cache, and
  `--cookies-from-browser` help.
- Automatic captions inherit speech recognition mistakes, especially with names
  and accents. Try `--asr always` with a bigger model, or the
  [local cleanup](#cleaning-up-a-transcript-with-a-local-ai-model).
- YouTube's translated captions are machine translations. Prefer the original
  language when you can.
- Private, members-only, and some age-restricted videos need
  `--cookies-from-browser`, and some can't be read at all.
- Live chat replays aren't supported. They aren't captions.

## Glossary

- **Captions:** the timed text YouTube shows under a video. *Manual* captions
  are written by the creator. *Automatic* captions are generated by YouTube's
  speech recognition.
- **ASR (automatic speech recognition):** turning speech into text. In this
  project, "local ASR" means transcribing the audio on your Mac.
- **Whisper:** a family of open speech recognition models. **whisper.cpp** and
  **MLX Whisper** are two programs that run Whisper models on a Mac.
- **MLX:** Apple's framework for running machine learning models on Apple silicon.
- **Model:** the file or folder of learned weights a speech or language engine
  needs. You download one once and reuse it.
- **yt-dlp:** a widely used open-source tool for reading YouTube pages and
  downloads. `ytt` uses it to find caption tracks.
